Teil I

Die Grundlagen

Was ist Angular, wie wird ein Projekt aufgesetzt, was ist eine Component, und wie binden wir Daten und Events. Alles, was du brauchst, bevor du ein eigenes Feature baust.

01 Was ist Angular?

Angular ist ein TypeScript-basiertes Framework von Google zum Bauen von Single-Page-Applications. Es liefert dir Components, Routing, Forms, HTTP, Dependency Injection und Build-Tools — alles in einem Paket. Stand Juni 2026 ist Angular 22 aktuell mit stabilen Signal Forms, Zoneless-Architektur und OnPush als Default.

Warum Angular?

  • Batteries included — Forms, Routing, HTTP, Testing alles dabei
  • TypeScript-first — saubere Typen für Templates, Inputs, Services
  • Signals — feingranulare Reaktivität ohne Zone.js
  • Standalone Components — kein NgModule-Overhead mehr
  • Enterprise-ready — Long-Term-Support, klare Update-Strategie
Stand 2026

Angular 22 ist die aktuelle Version. Signal Forms sind stable, OnPush ist Default für neue Components, Zoneless wird empfohlen, Vitest ist der primäre Test-Runner und Selectorless Components sind verfügbar.

04 Erste Component

Eine Component ist eine Klasse mit dem @Component-Decorator. Sie kombiniert Template (HTML), Style (CSS) und Logik (TypeScript) zu einer wiederverwendbaren Einheit.

Links · Aufbau
@Component()

Der Decorator macht aus einer Klasse eine Angular-Component.

selector

Der Tag-Name, mit dem du sie im HTML verwendest: <app-hello />

template

Inline-HTML. Alternativ templateUrl für eine separate Datei.

standalone

Default in v22, muss meist nicht gesetzt werden.

hello.ts
import { Component } from '@angular/core';

@Component({
  selector: 'app-hello',
  template: `
    <h1>Hallo {{ name }}!</h1>
    <p>Willkommen bei Angular.</p>
  `,
  styles: `
    h1 { color: #dd0031; font-family: sans-serif; }
  `
})
export class Hello {
  name = 'Welt';
}
Rechts · Tipp
Interpolation

{{ name }} bindet den Wert aus der Klasse ins Template — pures Lesen, keine Magie.

Backticks

Mehrzeilige Strings für Template/Styles. Mit ${} könntest du sogar Werte einbauen.

Naming

Klasse Hello, Datei hello.ts — kein .component-Suffix mehr ab v20.

05 Templates & Property Binding

Templates sind HTML mit drei Erweiterungen: {{ }} (Interpolation), [prop] (Property Binding) und später (event) (Event Binding).

Links · Erklärung
{{ expr }}

Schreibt den Wert von expr als Text in den DOM.

[attr]="expr"

Setzt eine DOM-Property (nicht das HTML-Attribut). Beispiel: [src], [disabled], [class.aktiv].

[class.x] / [style.y]

Bedingt eine Klasse setzen oder einen Style-Wert binden.

profile.ts & profile.html
@Component({
  selector: 'app-profile',
  template: `
    <img [src]="avatar" [alt]="name">
    <h2>{{ name }}</h2>
    <p [class.online]="isOnline">
      Status: {{ isOnline ? 'online' : 'offline' }}
    </p>
    <button [disabled]="!isOnline">
      Nachricht senden
    </button>
  `
})
export class Profile {
  name = 'Mara';
  avatar = '/mara.jpg';
  isOnline = true;
}
Rechts · Hinweis
Unterschied

src="..." = statischer String. [src]="..." = TypeScript-Ausdruck.

Sicherheit

Angular escaped Interpolation automatisch — kein XSS bei {{ user.name }}.

Conditional Style

[style.color]="isError ? 'red' : 'green'"

06 Event Binding

Mit (event)="handler($event)" reagierst du auf User-Aktionen. Der Handler ist eine Methode der Component-Klasse.

Links · Schritte
1. Signal anlegen

count = signal(0) — ein reaktiver Container.

2. Methode

Eine Funktion, die das Signal updatet.

3. Template

(click)="inc()" ruft die Methode beim Klick.

4. Anzeige

{{ count() }} — Signal aufrufen, um den Wert zu lesen.

counter.ts
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-counter',
  template: `
    <p>Zähler: {{ count() }}</p>
    <button (click)="inc()">+1</button>
    <button (click)="reset()">Reset</button>
  `
})
export class Counter {
  count = signal(0);

  inc() {
    this.count.update(v => v + 1);
    console.log('Neuer Wert:', this.count());
  }
  reset() {
    this.count.set(0);
  }
}
Rechts · Notiz
$event

Wenn du das DOM-Event brauchst: (input)="onInput($event)" und dann $event.target.value.

update vs set

set(5) = neuer Wert. update(v => v+1) = abhängig vom alten.

Signal lesen

Immer mit Klammern: count(), nicht count.

07 Two-way Binding mit Signals

Mit model() erstellst du ein Signal, das gleichzeitig Input und Output ist. Im Template nutzt du es mit [(ngModel)] oder [(value)].

Links · Erklärung
[(x)]

Die "Banana-in-a-Box" — Property Binding + Event Binding in einem.

ngModel

Die Standard-Two-way-Direktive für <input>. Braucht FormsModule.

Signal-basiert

Mit [(ngModel)] bindest du direkt an ein Signal — beim Tippen wird das Signal aktualisiert.

name-form.ts
import { Component, signal } from '@angular/core';
import { FormsModule } from '@angular/forms';

@Component({
  selector: 'app-name-form',
  imports: [FormsModule],
  template: `
    <input [(ngModel)]="name" placeholder="Name">
    <p>Hallo, {{ name() || '?' }}</p>
  `
})
export class NameForm {
  name = signal('');
}
Rechts · Tipp
imports

Standalone Components importieren ihre Abhängigkeiten direkt im Decorator.

Live-Updates

Jeder Tastenanschlag = Signal-Update = Template-Rerender.

Alternative

Ohne ngModel: (input)="name.set($event.target.value)"

Hallo, Mara

08 Control Flow — @if, @for, @switch

Seit v17 hat Angular eine eigene, schnellere Template-Syntax für Bedingungen und Schleifen. *ngIf und *ngFor sind out, @if und @for sind in.

Links · Erklärung
@if / @else

Eine Bedingung. Mit @else if verkettbar.

@for

Schleife mit Pflicht-Parameter track — sagt Angular, wie es Items identifiziert.

@empty

Wird gerendert, wenn die Liste leer ist.

@switch

Wie switch in JS, mit @case und @default.

todo-list.ts
@Component({
  selector: 'app-todos',
  template: `
    @if (todos().length > 0) {
      <ul>
        @for (todo of todos(); track todo.id) {
          <li>{{ todo.text }}</li>
        }
      </ul>
    } @else {
      <p>Keine Todos.</p>
    }

    @switch (status()) {
      @case ('loading') { <p>Lade…</p> }
      @case ('error')   { <p>Fehler!</p> }
      @default             { <p>Bereit.</p> }
    }
  `
})
export class TodoList {
  todos = signal([
    { id: 1, text: 'Angular lernen' },
    { id: 2, text: 'Kaffee trinken' }
  ]);
  status = signal<'loading'|'error'|'ok'>('ok');
}
Rechts · Notiz
track

Wichtig für Performance: Angular vergleicht Items über diesen Key.

$index, $first, $last

Innerhalb von @for verfügbar: {{ $index }}.

Migration

Alte *ngIf-Templates? ng generate @angular/core:control-flow

09 Built-in Pipes

Pipes transformieren Werte im Template — z. B. Datum, Zahlen, Strings, JSON. Syntax: {{ wert | pipe:arg }}.

Links · Pipes
date

Formatiert Date-Objekte oder Strings.

currency / number / percent

Zahlen mit Locale-bewusstem Formatieren.

uppercase / lowercase / titlecase

String-Transformationen.

json

Praktisch fürs Debugging im Template.

async

Subscribed automatisch auf Observables/Promises.

demo.ts
import { DatePipe, CurrencyPipe, UpperCasePipe,
         JsonPipe } from '@angular/common';

@Component({
  selector: 'app-demo',
  imports: [DatePipe, CurrencyPipe, UpperCasePipe, JsonPipe],
  template: `
    <p>{{ heute | date:'dd.MM.yyyy' }}</p>
    <p>{{ preis | currency:'CHF':'symbol' }}</p>
    <p>{{ user.name | uppercase }}</p>
    <pre>{{ user | json }}</pre>
  `
})
export class Demo {
  heute = new Date();
  preis = 19.9;
  user = { name: 'mara', age: 28 };
}
Rechts · Tipp
Verkettung

{{ datum | date:'short' | uppercase }} — Pipes kann man hintereinander hängen.

Locale

Für deutsche Formate provideLocale('de-CH') in app.config.ts.

Performance

Pipes sind pure — werden nur bei Wertänderung neu berechnet.

10 Signals — Reaktivität moderne Variante

Ein Signal ist ein Container für einen Wert, der weiss, wer ihn liest. Ändert sich der Wert, werden alle Leser informiert. Angular's neue Grundlage für Reaktivität.

Links · API
signal(init)

Erzeugt ein beschreibbares Signal.

Lesen

x() — als Funktion aufrufen.

Schreiben

x.set(neu) oder x.update(v => v+1).

Wo lesen?

Im Template, in computed, in effect. Überall sonst genauso — nur "merken" geht nur reaktiv.

cart.ts
import { signal } from '@angular/core';

const items = signal<string[]>([]);

console.log(items());        // []

items.set(['Apfel', 'Brot']);
console.log(items());        // ['Apfel', 'Brot']

items.update(list => [...list, 'Milch']);
console.log(items());        // ['Apfel', 'Brot', 'Milch']
Rechts · Notiz
Immer immutable

Nie list.push(...) — Signals erkennen Mutation nicht. Stattdessen neues Array bauen.

readonly

const view = items.asReadonly() — gibt nur Lese-Zugriff frei.

vs. RxJS

Signals sind sync, RxJS ist async. Beides hat seinen Platz.

Console
[]
[ 'Apfel', 'Brot' ]
[ 'Apfel', 'Brot', 'Milch' ]

11 computed & effect

computed() ist ein abgeleitetes, gecachtes Signal. effect() führt Code aus, wann immer ein gelesenes Signal sich ändert — perfekt für Logs, Persistierung, DOM-Updates ausserhalb des Templates.

Links · Erklärung
computed

Wird neu berechnet, wenn ein Quell-Signal sich ändert. Cached automatisch.

effect

Wird einmal initial ausgeführt und dann bei jeder Änderung eines darin gelesenen Signals.

Wann was?

computed = abgeleiteter Wert. effect = Seiteneffekt (Log, localStorage, etc.).

price.ts
import { signal, computed, effect } from '@angular/core';

const menge     = signal(2);
const stueck    = signal(4.5);

const total = computed(() => menge() * stueck());

effect(() => {
  console.log(`Total: CHF ${total().toFixed(2)}`);
});

menge.set(5);          // effect feuert
stueck.set(3.9);       // effect feuert wieder
Rechts · Tipp
Wo effect anlegen?

Im Constructor oder als Field-Initializer — Angular braucht injection context.

computed ist pure

Niemals Signals schreiben in einem computed — nur lesen.

Cleanup

effect bekommt einen onCleanup-Callback für Aufräumen.

Console
Total: CHF 9.00
Total: CHF 22.50
Total: CHF 19.50

12 input(), output(), model()

Components kommunizieren über Inputs (Daten rein) und Outputs (Events raus). Seit v17 gibt es die Signal-basierten Varianten input(), output() und model() — schöner als die alten @Input/@Output-Decorators.

Links · API
input()

Daten vom Parent rein. Optional mit Default oder .required().

output()

Event raus zum Parent. .emit(value) sendet es.

model()

Two-way-Input — Parent kann mit [(value)] binden.

like-button.ts
import { Component, input, output, model } from '@angular/core';

@Component({
  selector: 'app-like',
  template: `
    <p>{{ label() }}: {{ count() }}</p>
    <button (click)="inc()">👍</button>
  `
})
export class Like {
  // Pflicht-Input
  label = input.required<string>();
  // Two-way
  count = model(0);
  // Event raus
  liked = output<number>();

  inc() {
    this.count.update(v => v + 1);
    this.liked.emit(this.count());
  }
}

// Verwendung im Parent:
// <app-like label="Pizza" [(count)]="pizzaLikes" (liked)="onLike($event)"/>
Rechts · Notiz
required()

Compiler-Fehler, wenn Parent das Input vergisst.

Aliasing

input(0, { alias: 'foo' }) — anderer Name im Template.

Transform

input(0, { transform: numberAttribute }) wandelt z. B. String "5" automatisch in Zahl.

Console (Parent: (liked)="onLike($event)")
onLike → 1
onLike → 2
onLike → 3

13 Services & Dependency Injection

Logik, die nicht zu einer Component gehört (HTTP-Calls, State, Helper) landet in einem Service. Angulars DI-System gibt dir eine Instanz dort, wo du sie brauchst.

Links · Schritte
1. @Injectable

Markiert die Klasse als injizierbar. providedIn: 'root' = Singleton für die ganze App.

2. inject()

Die moderne Variante. Funktioniert in Constructor, Field-Init, Funktionen mit Injection-Context.

3. Nutzen

Service-Methoden aufrufen — Component bleibt schlank.

user.service.ts & profile.ts
import { Injectable, inject, signal } from '@angular/core';

@Injectable({ providedIn: 'root' })
export class UserService {
  user = signal({ name: 'Mara', age: 28 });

  rename(name: string) {
    this.user.update(u => ({ ...u, name }));
  }
}

@Component({
  selector: 'app-profile',
  template: `<p>{{ users.user().name }}</p>`
})
export class Profile {
  users = inject(UserService);
}
Rechts · Tipp
Singleton

providedIn: 'root' bedeutet: eine Instanz, geteilt überall.

Scoped Service

Im providers-Array einer Component → eigene Instanz pro Component-Baum.

inject vs. constructor

Beides funktioniert. inject() ist flexibler — auch in Funktionen.

14 HttpClient

Daten von einer API holen — HttpClient liefert Observables. Mit provideHttpClient() wird's registriert, mit inject() gezogen.

Links · Schritte
1. provideHttpClient()

In app.config.ts registrieren.

2. inject(HttpClient)

Im Service holen.

3. .get/.post/.put/.delete

Liefert ein Observable mit dem typisierten Response-Body.

4. subscribe

Oder besser: toSignal() für reaktive Templates.

posts.service.ts
import { Injectable, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';

interface Post { id: number; title: string; }

@Injectable({ providedIn: 'root' })
export class PostsService {
  private http = inject(HttpClient);

  getAll(): Observable<Post[]> {
    return this.http.get<Post[]>('/api/posts');
  }
}

// In Component:
const svc = inject(PostsService);
svc.getAll().subscribe(posts => console.log(posts));
Rechts · Notiz
Config

provideHttpClient(withFetch()) nutzt die native fetch-API.

toSignal()

Wandelt ein Observable in ein Signal — direkt im Template lesbar.

Error-Handling

RxJS catchError oder im Subscribe-Object { next, error }.

Console (Beispielantwort)

15 Routing

Mit dem Router wechselst du zwischen Views, ohne die Page neu zu laden. Routes werden als Array definiert und mit provideRouter() registriert.

Links · Aufbau
app.routes.ts

Array von Routes — Pfad + Component (oder loadComponent für Lazy).

RouterOutlet

Platzhalter im Template, wohin die aktive Route gerendert wird.

routerLink

Navigations-Direktive für Links — kein Page-Reload.

Params

Mit :id Pfad-Parameter definieren, mit input() in der Component lesen.

app.routes.ts & app.html
import { Routes } from '@angular/router';
import { Home } from './home';
import { About } from './about';

export const routes: Routes = [
  { path: '',        component: Home },
  { path: 'about',   component: About },
  { path: 'user/:id',
    loadComponent: () => import('./user')
                       .then(m => m.User) },
  { path: '**',      redirectTo: '' }
];

// app.html
<nav>
  <a routerLink="/">Home</a>
  <a routerLink="/about">Über</a>
</nav>

Rechts · Tipp
routerLinkActive

routerLinkActive="active" — markiert den aktiven Link.

Route Params

In der Ziel-Component: id = input<string>() + withComponentInputBinding().

Wildcards

** fängt alles ab, was nicht gematched wurde — gut für 404.

16 Lifecycle Hooks

Components haben ein Leben: erstellt, geupdated, zerstört. Mit Lifecycle-Hooks reagierst du auf diese Punkte. Mit Signals brauchst du sie seltener — effect() ist oft die bessere Wahl.

Links · Hooks
ngOnInit

Nach erster Property-Initialisierung — Daten laden, etc.

ngOnDestroy

Vor der Zerstörung — Subscriptions schliessen.

ngAfterViewInit

Nach erstem View-Render — Zugriff auf @ViewChild.

DestroyRef

Moderne Alternative: inject(DestroyRef).onDestroy(fn).

timer.ts
import { Component, OnInit, OnDestroy,
         signal } from '@angular/core';

@Component({
  selector: 'app-timer',
  template: `<p>Sekunden: {{ sec() }}</p>`
})
export class Timer implements OnInit, OnDestroy {
  sec = signal(0);
  private id?: number;

  ngOnInit() {
    console.log('Timer init');
    this.id = setInterval(
      () => this.sec.update(s => s+1), 1000);
  }

  ngOnDestroy() {
    console.log('Timer destroy');
    clearInterval(this.id);
  }
}
Rechts · Notiz
Cleanup ist Pflicht

Subscriptions, Intervalle, EventListener — alles in ngOnDestroy oder via DestroyRef.

Constructor vs OnInit

Im Constructor: DI ready. In OnInit: Inputs ready.

Modern

Mit Signals/effect brauchst du diese Hooks viel seltener.

Console (beim Öffnen + nach 3s navigieren)

// nach 3 Sekunden:
Timer destroy

17 Custom Pipes

Eine Pipe ist eine Klasse mit transform(). Eigene Pipes baust du genauso wie die eingebauten — z. B. für domänenspezifische Formatierungen.

Links · Schritte
1. @Pipe

Decorator mit name — der Name, unter dem die Pipe im Template verfügbar ist.

2. PipeTransform

Interface mit transform(value, ...args).

3. imports

Pipe in die Component-imports aufnehmen.

truncate.pipe.ts
import { Pipe, PipeTransform } from '@angular/core';

@Pipe({ name: 'truncate' })
export class TruncatePipe implements PipeTransform {
  transform(value: string, limit = 20): string {
    return value.length > limit
      ? value.slice(0, limit) + '…'
      : value;
  }
}

// Verwendung:
// imports: [TruncatePipe]
// {{ text | truncate:30 }}

console.log(new TruncatePipe().transform(
  'Das hier ist ein sehr langer Text', 15));
Rechts · Tipp
Pure vs Impure

Default: pure (neu berechnen nur bei Wertänderung). { pure: false } für Listen-Mutationen — aber Performance-Falle.

Argumente

Beliebig viele: {{ x | foo:a:b:c }}.

18 Custom Directives

Directives sind wie Components ohne Template — sie hängen Verhalten an existierende Elemente. Ideal für Tooltips, Auto-Focus, Highlight-Effekte.

Links · Aufbau
@Directive

Statt @Component — mit selector als CSS-Attribut-Selektor.

HostListener

Reagiert auf DOM-Events am Host-Element.

HostBinding

Setzt Properties/Klassen/Styles am Host.

ElementRef

Zugriff aufs native DOM-Element (sparsam einsetzen).

highlight.directive.ts
import { Directive, input, HostListener,
         HostBinding } from '@angular/core';

@Directive({ selector: '[appHighlight]' })
export class Highlight {
  color = input('yellow', { alias: 'appHighlight' });

  @HostBinding('style.background')
  bg: string = '';

  @HostListener('mouseenter') onIn() {
    this.bg = this.color();
  }
  @HostListener('mouseleave') onOut() {
    this.bg = '';
  }
}

// <p [appHighlight]="'lightcoral'">Hover mich!</p>
Rechts · Notiz
Selector-Konvention

Eckige Klammern [xy] = Attribut-Selektor. Mit Prefix (z. B. app) für eigene Directives.

Structural Directives

Wie *ngIf — heute nimmst du lieber @if.

19 Reactive Forms

Für komplexere Formulare mit Validierung baust du das Form-Modell programmatisch: FormGroup, FormControl, FormArray. Reaktiv über Observables.

Links · Schritte
1. ReactiveFormsModule

In imports der Component.

2. FormBuilder

Mit inject(FormBuilder) bauen.

3. Template-Bindings

[formGroup], formControlName verbinden HTML und Modell.

4. Validators

Eingebaut: required, email, minLength, ... oder eigene.

login.ts
import { Component, inject } from '@angular/core';
import { FormBuilder, Validators,
         ReactiveFormsModule } from '@angular/forms';

@Component({
  selector: 'app-login',
  imports: [ReactiveFormsModule],
  template: `
    <form [formGroup]="form" (ngSubmit)="submit()">
      <input formControlName="email">
      <input formControlName="pass" type="password">
      <button [disabled]="form.invalid">Login</button>
    </form>
  `
})
export class Login {
  private fb = inject(FormBuilder);

  form = this.fb.group({
    email: ['', [Validators.required, Validators.email]],
    pass:  ['', [Validators.minLength(8)]]
  });

  submit() {
    console.log(this.form.value);
  }
}
Rechts · Tipp
valueChanges

Observable für Live-Werte. Mit toSignal() auch als Signal nutzbar.

Custom Validator

Funktion (c: AbstractControl) => ValidationErrors|null.

Nested Forms

20 Signal Forms v22

Die neue Form-API ist seit v22 stable. Statt FormGroup/FormControl bindest du direkt Signals — weniger Boilerplate, volle Typsicherheit, Validierung als Predicate.

Links · Erklärung
form()

Erzeugt ein Form aus einem Signal-State.

Schema

Validierung als Funktionen — komplett typsicher.

Im Template

[control] bindet Input ans Form-Field, .valid(), .touched(), .errors() als Signals.

signup.ts
import { Component, signal } from '@angular/core';
import { form, required, minLength,
         Control } from '@angular/forms/signals';

@Component({
  selector: 'app-signup',
  imports: [Control],
  template: `
    <input [control]="f.name" placeholder="Name">
    <input [control]="f.email" placeholder="E-Mail">
    @if (!f.valid()) { <p>Bitte ausfüllen.</p> }
    <button [disabled]="!f.valid()" (click)="save()">
      Speichern
    </button>
  `
})
export class Signup {
  state = signal({ name: '', email: '' });

  f = form(this.state, (s) => {
    required(s.name);
    required(s.email);
    minLength(s.name, 2);
  });

  save() {
    console.log(this.f.value());
  }
}
Rechts · Notiz
Vorteil

Form-State ist ein Signal — computed/effect direkt nutzbar.

Validierung

Pure Funktionen, alles inferred. Eigene Validatoren = einfach eigene Funktionen.

Migration

Reactive Forms funktionieren weiter — nicht Pflicht zu migrieren.

Console (nach Save)
{ name: 'Mara', email: 'mara@example.ch' }

21 Route Guards

Guards entscheiden, ob ein Route-Wechsel passieren darf. Z. B. canActivate für Auth, canDeactivate für ungespeicherte Änderungen. Seit v15+ als Funktionen statt Klassen.

Links · Erklärung
Functional Guard

Einfache Funktion, die boolean oder UrlTree zurückgibt (sync oder async).

inject()

Da Guards Funktionen sind, brauchst du inject() für Services.

Route-Config

Im Route-Objekt: canActivate: [authGuard].

auth.guard.ts
import { inject } from '@angular/core';
import { Router, CanActivateFn } from '@angular/router';
import { AuthService } from './auth.service';

export const authGuard: CanActivateFn = () => {
  const auth   = inject(AuthService);
  const router = inject(Router);

  if (auth.isLoggedIn()) return true;
  return router.createUrlTree(['/login']);
};

// In den Routes:
{ path: 'admin', component: Admin,
  canActivate: [authGuard] }
Rechts · Notiz
Async Guards

Geben Promise oder Observable zurück — der Router wartet.

Andere Guards

canDeactivate, canMatch, resolve (Daten vorladen).

22 HTTP Interceptors

Interceptors hängen sich zwischen HttpClient und Server — perfekt für Auth-Header, Logging, Error-Handling. Auch hier als Funktion.

Links · Schritte
HttpInterceptorFn

Funktion mit Signatur (req, next) => next(req).

Request klonen

Requests sind immutable — req.clone({ setHeaders: ... }).

Registrieren

In provideHttpClient(withInterceptors([fn])).

auth.interceptor.ts
import { HttpInterceptorFn } from '@angular/common/http';
import { inject } from '@angular/core';
import { AuthService } from './auth.service';

export const authInterceptor: HttpInterceptorFn =
  (req, next) => {
    const token = inject(AuthService).getToken();
    const authReq = token
      ? req.clone({
          setHeaders: { Authorization: `Bearer ${token}` }
        })
      : req;
    console.log('→', authReq.method, authReq.url);
    return next(authReq);
  };

// app.config.ts
provideHttpClient(withInterceptors([authInterceptor]))
Rechts · Tipp
Kette

Mehrere Interceptors: laufen in der Reihenfolge der Array-Einträge.

Response abfangen

return next(req).pipe(tap(...)) für Logging der Response.

Console
→ GET /api/posts
→ POST /api/login

23 Lazy Loading

Statt alle Components ins Initial-Bundle zu packen, lädst du sie erst, wenn sie gebraucht werden. Massiver Performance-Boost für grosse Apps.

Links · Optionen
loadComponent

Lädt eine einzelne Component nach.

loadChildren

Lädt einen ganzen Sub-Route-Tree.

defer (Template)

Lazy-Loading auf Template-Ebene — siehe Kapitel 25.

app.routes.ts
export const routes: Routes = [
  { path: '', component: Home },

  // Einzelne Component lazy
  { path: 'profil',
    loadComponent: () =>
      import('./profil/profil').then(m => m.Profil) },

  // Ganze Feature lazy
  { path: 'admin',
    loadChildren: () =>
      import('./admin/admin.routes')
        .then(m => m.ADMIN_ROUTES) }
];
Rechts · Notiz
Build-Output

Lazy-Routes landen in eigenen Chunk-Files.

Preloading

withPreloading(PreloadAllModules) lädt im Hintergrund nach Initial-Render.

Trade-off

Initial-Load schneller, aber kurzer Spinner beim ersten Aufruf der lazy-Route.

terminal — ng build
$ ng build Initial chunk files | Names | Raw size main.js | main | 187.42 kB polyfills.js | polyfills | 34.58 kB Lazy chunk files | Names | Raw size chunk-A1B2.js | profil | 12.18 kB chunk-C3D4.js | admin | 41.92 kB ✔ Application bundle generation complete.

24 Zoneless & OnPush

Zone.js patched async APIs, damit Angular weiss, wann es prüfen muss. Mit Signals brauchst du das nicht mehr. Zoneless = ohne Zone.js, ChangeDetection läuft signalgetrieben. Ab v22 der empfohlene Default.

Links · Erklärung
Zoneless aktivieren

provideZonelessChangeDetection() in app.config.ts.

OnPush

Component prüft Template nur bei Input-Change oder Signal-Update. v22 setzt es als Default.

Was geht nicht?

Globale Mutation ohne Signal triggert kein Update. Sauberes Signal-Modell ist Pflicht.

app.config.ts & component
import { provideZonelessChangeDetection,
         ChangeDetectionStrategy } from '@angular/core';

export const appConfig: ApplicationConfig = {
  providers: [
    provideZonelessChangeDetection(),
    provideRouter(routes),
    provideHttpClient()
  ]
};

@Component({
  selector: 'app-fast',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `<p>{{ wert() }}</p>`
})
export class Fast {
  wert = signal(0);
}
Rechts · Tipp
Performance

Zoneless-Apps haben deutlich kleinere Bundles (kein zone.js) und schnellere CD.

Migration

Erst alles auf Signals umstellen, dann Zone weglassen.

Debugging

"Warum updated sich's nicht?" → meistens: kein Signal, sondern Plain-Property.

25 Resource API, SSR & @defer

Drei moderne Features, die du in echten Apps brauchst: resource() für asynchrones Laden, SSR/Hydration für SEO und schnellen Initial-Load, @defer für lazy Template-Blöcke.

Resource API

Links · resource()
Reaktiv laden

Loader-Funktion + Param-Signal = Auto-Refetch beim Param-Change.

States

.value(), .isLoading(), .error() — alles Signals.

user-detail.ts
import { Component, input, resource } from '@angular/core';

@Component({
  selector: 'app-user',
  template: `
    @if (user.isLoading()) { <p>Lade…</p> }
    @else if (user.error()) { <p>Fehler!</p> }
    @else { <h2>{{ user.value()?.name }}</h2> }
  `
})
export class UserDetail {
  id = input.required<string>();

  user = resource({
    params: () => ({ id: this.id() }),
    loader: async ({ params }) => {
      const res = await fetch(`/api/users/${params.id}`);
      return res.json();
    }
  });
}
Rechts · Notiz
Auto-Refetch

Ändert sich id, lädt resource() neu.
