Teil I

Die Grundlagen

Was TypeScript ist, wie du es installierst und die Bausteine, mit denen alles andere arbeitet — Typen, Variablen, Funktionen.

01Was ist TypeScript?

TypeScript ist eine von Microsoft entwickelte Sprache, die JavaScript um ein statisches Typsystem erweitert. Der TypeScript-Compiler übersetzt deinen Code zurück nach JavaScript — das eigentliche Browser-/Node-Programm bleibt JS.

Warum überhaupt Typen? JavaScript ist sehr nachsichtig — Fehler tauchen erst zur Laufzeit auf. TypeScript erkennt sie schon beim Tippen.

Links · Erklärung
Das Problem in JS

In reinem JavaScript kann man "5" (String) und 3 (Number) einfach mit + verknüpfen — das Ergebnis ist eine Stringverkettung statt einer Addition.

Niemand warnt dich. Der Fehler fällt erst auf, wenn die Anwendung läuft — vielleicht erst beim Kunden.

// reines JavaScript
function addiere(a, b) {
  return a + b;
}

console.log(addiere("5", 3));
console.log(addiere(5, 3));
Rechts · Notiz
Tückisch

Solche Bugs treten in echten Projekten ständig auf — meistens, weil Daten aus einer API oder einem Formular als String kommen, obwohl man Zahlen erwartet.

Konsolen-Output
"53"   // ← keine Addition, sondern Verkettung!
8      // hier funktioniert es zufällig

Mit TypeScript schreiben wir dieselbe Funktion mit Typangaben:

Links · Erklärung
Typen als Verträge

a: number ist eine Zusage: „Hier darf nur eine Zahl rein."

Der Compiler prüft beim Schreiben, ob alle Aufrufe diese Regel einhalten.

// TypeScript
function addiere(a: number, b: number): number {
  return a + b;
}

addiere("5", 3); // ← Fehler!
addiere(5, 3);   // ✓ ok
Rechts · Was passiert
Bug abgefangen

Der erste Aufruf wird vom Compiler abgelehnt — der Code wird gar nicht erst zu JavaScript übersetzt.

Argument of type 'string' is not assignable to parameter of type 'number'.

02Installation & Setup

TypeScript ist ein npm-Paket. Du brauchst Node.js, dann installierst du den Compiler entweder global oder pro Projekt.

Links · Was tun wir?
Schritt für Schritt

1. Neues Projekt anlegen

2. TypeScript als Dev-Dependency

3. Eine Konfigurationsdatei (tsconfig.json) erzeugen

4. Code schreiben und kompilieren

# Projekt initialisieren
npm init -y

# TypeScript installieren
npm install -D typescript

# tsconfig.json erzeugen
npx tsc --init

# Kompilieren
npx tsc

# Direkt ausführen (mit tsx)
npx tsx index.ts
Rechts · Hinweis
tsx vs. tsc

tsc ist der offizielle Compiler — er erzeugt .js-Dateien.

tsx oder ts-node führen TypeScript direkt aus, ohne Build-Schritt — praktisch für Skripte und Entwicklung.

Eine sinnvolle tsconfig.json

Links · Erklärung

strict: true ist die wichtigste Option — sie aktiviert alle strengen Prüfungen auf einmal.

target legt fest, in welche JavaScript-Version kompiliert wird.
"target": "ESNext" sorgt dafür, dass TypeScript den erzeugten JavaScript-Code auf die neueste verfügbare ECMAScript-Version ausrichtet und moderne Sprachfeatures beibehält.

outDir bestimmt den Zielordner.

{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "outDir": "./dist",
    "rootDir": "./src"
  },
  "include": ["src/**/*"]
}
Rechts · Tipp
Strict immer an

Ohne strict nimmst du dir die Hälfte der Vorteile von TypeScript. Schalte es vom ersten Tag an ein.

03Primitive Typen

TypeScript kennt dieselben Primitiv-Typen wie JavaScript — nur dass wir sie jetzt benennen können.

Links · Erklärung
Die Basis-Typen

string für Text, number für alle Zahlen (Integer + Float), boolean für wahr/falsch.

bigint für riesige Ganzzahlen, symbol für eindeutige Identifikatoren — eher selten gebraucht.

Die Syntax variable: typ = wert nennt man Typannotation.

const name: string = "Anna";
const alter: number = 29;
const istAdmin: boolean = true;
const groß: bigint = 9007199254740993n;
const id: symbol = Symbol("user");

console.log(name, alter, istAdmin);
console.log(typeof alter);
Rechts · Output erklärt

Die erste Zeile gibt die drei Werte aus, getrennt durch Leerzeichen.

typeof ist ein JS-Operator und gibt den Laufzeit-Typ als String zurück — bei Zahlen also "number".

Konsolen-Output
Anna 29 true
number

04Arrays & Tuples

Listen von Werten — wahlweise mit gleichem Typ (Array) oder einer festen Reihenfolge unterschiedlicher Typen (Tuple).

Arrays

Links · Erklärung
Zwei Schreibweisen

number[] und Array<number> sind exakt das Gleiche — meistens wird die kurze Form bevorzugt.

Versucht man, ein anderes Element hinzuzufügen (z.B. einen String in ein Number-Array), beschwert sich der Compiler sofort.

const zahlen: number[] = [1, 2, 3];
const namen: Array<string> = ["Anna", "Ben"];

zahlen.push(4);     // ✓ ok
zahlen.push("5");   // ✗ Fehler

console.log(zahlen);
console.log(namen.length);
Rechts · Was passiert

Nur das gültige push(4) wird ausgeführt — das ungültige wird vom Compiler abgelehnt.

Im Output sieht man das Array mit der angehängten 4.

Konsolen-Output
[ 1, 2, 3, 4 ]
2

Tuples

Links · Erklärung
Feste Reihenfolge

Ein Tuple ist ein Array mit fester Länge und festen Typen pro Position.

Praktisch für Koordinaten, Schlüssel-Wert-Paare oder Hooks (z.B. React's useState liefert ein Tuple).

type Punkt = [number, number];

const p: Punkt = [10, 20];

// Tuple mit Labels (nur Doku, kein Effekt)
type User = [id: number, name: string];
const u: User = [1, "Anna"];

console.log(p[0], p[1]);
console.log(u);
Rechts · Tipp
Destructuring

Tuples lassen sich super destructuren:

const [id, name] = u;

Genau so funktioniert useState in React.

Konsolen-Output
10 20
[ 1, 'Anna' ]

05Objekte & Type Aliases

Objekt-Typen beschreiben die Form (Shape) eines Objekts — welche Eigenschaften es hat und welchen Typ jede einzelne hat.

Links · Erklärung
Inline vs. benannt

Man kann den Typ direkt anschreiben (inline) — bei wiederholter Nutzung lohnt es sich aber, ihn mit type einen Namen zu geben.

Das ? hinter einem Property macht es optional.

readonly verhindert spätere Änderungen.

// Inline-Typ
const user1: { name: string; alter: number } = {
  name: "Anna",
  alter: 29
};

// Benannter Type Alias
type User = {
  readonly id: number;
  name: string;
  email?: string;  // optional
};

const user2: User = { id: 1, name: "Ben" };
user2.email = "ben@example.com";
user2.id = 2; // ✗ readonly!

console.log(user2);
Rechts · Output erklärt

Die letzte Zeile (user2.id = 2) wird vom Compiler abgelehnt — aber alle gültigen Zuweisungen davor laufen durch.

Das Objekt hat jetzt id, name und nachträglich gesetzte email.

Konsolen-Output
{ id: 1, name: 'Ben', email: 'ben@example.com' }
Cannot assign to 'id' because it is a read-only property.

06Union & Literal Types

Mit | sagst du: „Dieser Wert darf einer von mehreren Typen sein." Literal-Typen schränken auf konkrete Werte ein.

Links · Erklärung
Union

string | number heisst: entweder ein String oder eine Zahl — nichts anderes.

Literal-Type

"klein" | "mittel" | "gross" erlaubt nur exakt diese drei Strings — wie ein einfaches Enum. 

// Union
let id: string | number;
id = 42;
id = "abc";

// Literal Type
type Grösse = "klein" | "mittel" | "gross";

function pizza(g: Grösse): number {
  if (g === "klein")  return 10;
  if (g === "mittel") return 14;
  return 18;
}

console.log(pizza("mittel"));
console.log(pizza("XL"));  // ✗ Fehler
Rechts · Notiz
Autovervollständigung

Bei Literal-Types schlägt dein Editor automatisch die erlaubten Werte vor — du musst sie dir nicht merken.

Ein Tippfehler („mittl") fällt sofort auf.

Konsolen-Output
14
Argument of type '"XL"' is not assignable to parameter of type 'Grösse'.

07Funktionen

Bei Funktionen typisierst du Parameter und optional den Rückgabetyp. Den Rückgabetyp kann TS oft selbst erkennen — explizit angeben macht den Vertrag aber klarer.

Links · Erklärung
Drei Formen

1. Klassische Function Declaration

2. Arrow Function in einer Konstante

3. Funktionstyp vorab definieren und dann anwenden

Das ? macht einen Parameter optional, = setzt einen Default.

// 1) Function Declaration
function begrüße(name: string): string {
  return `Hallo, ${name}!`;
}

// 2) Arrow Function
const verdoppele = (x: number): number => x * 2;

// 3) Vorab typisierte Funktion
type Rechner = (a: number, b: number) => number;
const multipl: Rechner = (a, b) => a * b;

// Optional + Default
function log(msg: string, level: string = "info") {
  console.log(`[${level}] ${msg}`);
}

console.log(begrüße("Anna"));
console.log(verdoppele(7));
console.log(multipl(3, 4));
log("Server gestartet");
log("Datenbank weg", "error");
Rechts · Output erklärt

begrüße liefert den eingesetzten String.

verdoppele(7) ergibt 14, multipl(3,4) ergibt 12.

Der erste log nutzt den Default "info", der zweite überschreibt ihn mit "error".

Konsolen-Output
Hallo, Anna!
14
12
[info] Server gestartet
[error] Datenbank weg

Rest-Parameter & void

Links · Erklärung

Mit ... nimmst du beliebig viele Argumente entgegen — sie landen als Array im Parameter.

void als Rückgabetyp heisst: „Die Funktion gibt nichts Sinnvolles zurück."

function summe(...zahlen: number[]): number {
  return zahlen.reduce((a, b) => a + b, 0);
}

function warne(msg: string): void {
  console.warn("⚠ " + msg);
}

console.log(summe(1, 2, 3, 4, 5));
warne("Speicher knapp");
Rechts · Notiz

reduce faltet das Array zu einem Wert zusammen — hier zur Summe.

console.warn ist wie log, nur als Warnung markiert.

Konsolen-Output
15
⚠ Speicher knapp

08Type Inference

TypeScript ist clever — du musst nicht überall Typen anschreiben. Aus der Zuweisung wird der Typ automatisch erkannt.

Links · Erklärung
Lass TS arbeiten

Bei const x = 5 weiss TS sofort: das ist number. Eine Annotation wäre überflüssig.

Auch der Rückgabetyp einer Funktion wird aus dem return abgeleitet.

Wann doch Annotation? An den Schnittstellen — bei Funktions-Parametern und öffentlichen APIs.

// Inferred als number
const x = 5;

// Inferred als string
const gruß = "Hallo";

// Inferred als string[]
const liste = ["a", "b", "c"];

// Rückgabe inferred als number
function quadrat(n: number) {
  return n * n;
}

const ergebnis = quadrat(8);
console.log(ergebnis, typeof ergebnis);
Rechts · Tipp
Hover im Editor

Im Editor zeigt dir der Hover über jede Variable den abgeleiteten Typ. Probier's aus — das ist eines der schönsten Features.

Konsolen-Output
64 number

09any, unknown, never

Drei Spezial-Typen, die du verstehen musst — vor allem den Unterschied zwischen any (Notausgang) und unknown (sicherer Notausgang).

Links · Erklärung
any — schaltet alles aus

Mit any sagst du TS: „Hör auf zu prüfen." Du verlierst alle Vorteile. Nur im absoluten Notfall verwenden.

unknown — sicherer any

Bei unknown musst du den Typ erst prüfen, bevor du etwas damit machen darfst.

never — kommt nie zurück

Funktionen, die immer einen Fehler werfen oder ewig laufen, haben Rückgabetyp never.

// any: erlaubt alles, prüft nichts
let a: any = 5;
a = "jetzt ein String";
a.irgendwas();  // kein Fehler – aber Crash zur Laufzeit!

// unknown: typsicher
let u: unknown = "text";
// u.toUpperCase();  ✗ Fehler – Typ erst prüfen!
if (typeof u === "string") {
  console.log(u.toUpperCase());
}

// never: Funktion kehrt nie zurück
function abbruch(msg: string): never {
  throw new Error(msg);
}

try { abbruch("Fataler Fehler"); }
catch (e) { console.log((e as Error).message); }
Rechts · Faustregel
any vermeiden

Wann immer du any tippst, frag dich: geht auch unknown?

In 95 % der Fälle ist die Antwort ja — und du behältst die Typsicherheit.

Konsolen-Output
TEXT
Fataler Fehler

Die Mittelstufe

Strukturen für grössere Programme — Interfaces, Klassen, Enums und ein erster Blick auf Generics.

10Interfaces

Ein interface beschreibt die Form eines Objekts — sehr ähnlich zu type, mit ein paar eigenen Stärken (z.B. erweiterbar, ideal für Klassen-Verträge).

Links · Erklärung
extends

Interfaces können andere Interfaces erweitern und neue Felder hinzufügen.

implements

Eine Klasse mit implements verpflichtet sich, alle Felder/Methoden des Interfaces zu liefern.

type vs. interface

Für Objekt-Shapes nimmt man oft interface, für Unions, Tuples und Mapped Types type.

interface Person {
  name: string;
  alter: number;
}

interface Mitarbeiter extends Person {
  firma: string;
  gehalt: number;
}

const m: Mitarbeiter = {
  name: "Anna",
  alter: 29,
  firma: "Acme",
  gehalt: 75000
};

// Methoden im Interface
interface Tier {
  name: string;
  spricht(): string;
}

class Hund implements Tier {
  constructor(public name: string) {}
  spricht() { return "Wuff!"; }
}

const rex = new Hund("Rex");
console.log(m.name, m.firma);
console.log(rex.name, rex.spricht());
Rechts · Output erklärt

Mitarbeiter bekommt alle Felder von Person dazu — du musst sie nicht doppelt schreiben.

Die Hund-Klasse muss name und spricht() liefern, sonst gibt es einen Compilerfehler.

Konsolen-Output
Anna Acme
Rex Wuff!

11Klassen

Klassen funktionieren wie in modernem JavaScript — TypeScript ergänzt sie um Sichtbarkeits-Modifier (public, private, protected) und mehr.

Links · Erklärung
Modifier

public — überall zugreifbar (default).
private — nur in dieser Klasse.
protected — in dieser und abgeleiteten Klassen.
readonly — nach Constructor nicht mehr änderbar.

Parameter Properties

constructor(public name: string) ist Kurzform für: Parameter plus automatisches Property mit gleichem Namen.

class Konto {
  private stand: number = 0;

  constructor(
    public readonly inhaber: string,
    start: number = 0
  ) {
    this.stand = start;
  }

  einzahlen(betrag: number): void {
    if (betrag <= 0) throw new Error("> 0!");
    this.stand += betrag;
  }

  get saldo(): number {
    return this.stand;
  }
}

const k = new Konto("Anna", 100);
k.einzahlen(50);

console.log(k.inhaber);
console.log(k.saldo);
// k.stand   ✗ private
// k.inhaber = "Ben"  ✗ readonly
Rechts · Tipp
Getter ohne Klammern

get saldo() wird als Property aufgerufen: k.saldo — nicht k.saldo().

Das fühlt sich an wie ein Feld, ist aber gleichzeitig eine Funktion, die berechnen kann.

Konsolen-Output
Anna
150

Vererbung mit extends

Links · Erklärung

Mit extends erbt eine Klasse von einer anderen.

super(...) ruft den Constructor der Elternklasse auf.

abstract macht eine Klasse nicht-instanziierbar — sie ist nur als Basis gedacht.

abstract class Form {
  abstract fläche(): number;
  beschreibe(): string {
    return `Fläche: ${this.fläche()}`;
  }
}

class Kreis extends Form {
  constructor(private r: number) { super(); }
  fläche() { return Math.PI * this.r ** 2; }
}

class Quadrat extends Form {
  constructor(private s: number) { super(); }
  fläche() { return this.s ** 2; }
}

const formen: Form[] = [new Kreis(5), new Quadrat(4)];
for (const f of formen) console.log(f.beschreibe());
Rechts · Output erklärt

Beide Subklassen erben beschreibe(), müssen aber fläche() selbst liefern.

Die Schleife arbeitet mit Form — egal, was konkret drinsteht.

Konsolen-Output
Fläche: 78.53981633974483
Fläche: 16

12Enums

Enums (kurz für Enumerations) gruppieren benannte Konstanten. Inzwischen verwenden viele Teams lieber as const-Objekte oder Union-Literals — aber Enums sind weiterhin gültig und gängig.

Links · Erklärung
Numerische Enums

Ohne Wert beginnen sie bei 0 und zählen hoch.

String-Enums

Jedem Mitglied wird ein expliziter String zugewiesen — übersichtlicher in Logs und APIs.

const enum

Wird zur Compile-Zeit inlined — kein zusätzliches JS-Objekt zur Laufzeit, aber mit Einschränkungen.

// Numerisches Enum
enum Richtung {
  Oben,    // 0
  Unten,   // 1
  Links,   // 2
  Rechts   // 3
}

// String-Enum
enum Status {
  Aktiv = "ACTIVE",
  Pausiert = "PAUSED",
  Gelöscht = "DELETED"
}

function bewege(r: Richtung): string {
  return Richtung[r];
}

console.log(Richtung.Oben);
console.log(bewege(Richtung.Rechts));
console.log(Status.Aktiv);
Rechts · Tipp
Moderne Alternative

Viele bevorzugen heute:

const Status = {
  Aktiv: "ACTIVE",
  Pausiert: "PAUSED"
} as const;

type Status =
  typeof Status[keyof typeof Status];
Konsolen-Output
0
Rechts
ACTIVE

13Generics — die Grundlagen

Generics sind Platzhalter für Typen. Damit schreibst du Funktionen und Klassen, die mit beliebigen Typen funktionieren — und trotzdem typsicher bleiben.

Links · Erklärung
Das Problem

Eine Funktion, die genau zurückgibt, was sie bekommt — egal welcher Typ. Mit any würden wir die Typinfo verlieren.

Die Lösung

<T> ist ein Typ-Parameter. Beim Aufruf füllt TS ihn automatisch mit dem konkreten Typ.

Die Konvention ist T (Type), K (Key), V (Value), U (zweiter Typ).

// Identität: gibt zurück, was reinkommt
function identität<T>(wert: T): T {
  return wert;
}

const a = identität(42);          // T = number
const b = identität("hallo");     // T = string
const c = identität<boolean>(true); // explizit

// Generische Funktion: erstes Element holen
function erstes<T>(arr: T[]): T | undefined {
  return arr[0];
}

console.log(a, b, c);
console.log(erstes([10, 20, 30]));
console.log(erstes(["a", "b"]));
console.log(erstes([]));
Rechts · Output erklärt

Beim Aufruf erstes([10,20,30]) wird T automatisch zu number — die Rückgabe ist also typsicher number | undefined.

Ein leeres Array liefert undefined.

Konsolen-Output
42 hallo true
10
a
undefined

Generische Klasse

Links · Erklärung

Auch Klassen können generisch sein — perfekt für Container wie Stacks, Queues oder Caches.

Der Typ-Parameter steht hinter dem Klassennamen.

class Stack<T> {
  private items: T[] = [];
  push(item: T) { this.items.push(item); }
  pop(): T | undefined { return this.items.pop(); }
  get size() { return this.items.length; }
}

const s = new Stack<string>();
s.push("erste");
s.push("zweite");

console.log(s.size);
console.log(s.pop());
console.log(s.size);
Rechts · Notiz

new Stack<string>() erzeugt einen Stack, der nur Strings akzeptiert.

Ein Versuch wie s.push(42) wird sofort abgelehnt.

Konsolen-Output
2
zweite
1

14Type Guards

Type Guards sind Prüfungen, die TypeScript verstehen und innerhalb des if-Blocks zur Verengung des Typs nutzen kann.

Links · Erklärung
Eingebaute Guards

typeof — für Primitive (string, number, boolean ...).

instanceof — für Klassen-Instanzen.

in — prüft, ob ein Property existiert.

User-defined Guard

Mit x is Type als Rückgabetyp kannst du eigene Guards bauen.

// typeof-Guard
function drucke(v: string | number) {
  if (typeof v === "string") {
    // hier ist v: string
    console.log(v.toUpperCase());
  } else {
    // hier ist v: number
    console.log(v.toFixed(2));
  }
}

// instanceof-Guard
class Katze { miaut() { return "Miau"; } }
class Hund  { bellt() { return "Wuff"; } }

function geräusch(t: Katze | Hund) {
  if (t instanceof Katze) return t.miaut();
  return t.bellt();
}

// User-defined Guard
type Fisch = { schwimm: () => void };
function istFisch(x: any): x is Fisch {
  return x && typeof x.schwimm === "function";
}

drucke("hallo");
drucke(3.14159);
console.log(geräusch(new Katze()));
console.log(geräusch(new Hund()));
Rechts · Output erklärt

Im if (typeof v === "string")-Zweig weiss TS: v ist ein String — also darf .toUpperCase() aufgerufen werden.

Das nennt sich Narrowing.

Konsolen-Output
HALLO
3.14
Miau
Wuff

15Optional Chaining & Nullish Coalescing

Zwei extrem nützliche JS-Features, die im TypeScript-Alltag ständig vorkommen.

Links · Erklärung
?. — Optional Chaining

Greift nur dann auf das Property zu, wenn das davor weder null noch undefined ist. Sonst liefert es einfach undefined, ohne zu crashen.

?? — Nullish Coalescing

Liefert die rechte Seite nur, wenn die linke null oder undefined ist. Im Gegensatz zu || behält es 0 und "" als gültige Werte.

type User = {
  name: string;
  adresse?: { stadt?: string };
  posts?: number;
};

const u1: User = { name: "Anna" };
const u2: User = {
  name: "Ben",
  adresse: { stadt: "Zürich" },
  posts: 0
};

// Optional Chaining
console.log(u1.adresse?.stadt);
console.log(u2.adresse?.stadt);

// Nullish Coalescing
console.log(u1.adresse?.stadt ?? "unbekannt");
console.log(u2.posts ?? "keine");
console.log(u2.posts || "keine");
Rechts · Wichtig
?? vs. ||

Bei u2.posts = 0:

?? "keine" → 0 (0 ist gültig)

|| "keine" → "keine" (0 ist falsy)

Das ist genau der Unterschied — und der Grund, warum man heute meistens ?? nimmt.

Konsolen-Output
undefined
Zürich
unbekannt
0
keine

16Type Assertions

Manchmal weisst du als Entwickler mehr über einen Wert als TS. Mit einer Type Assertion sagst du dem Compiler: „Vertrau mir, das ist Typ X."

Links · Erklärung
as

Die Standard-Syntax. Funktioniert auch in JSX/TSX-Dateien (im Gegensatz zur alten <Type>-Syntax).

! — Non-null Assertion

x! sagt: „Ich garantiere, x ist nicht null oder undefined."

satisfies

Prüft, dass ein Wert einem Typ entspricht, ohne den Typ zu verengen.

// "as" verwendet, weil wir wissen, dass JSON ein User ist
const data = JSON.parse('{"name":"Anna","alter":29}');
const user = data as { name: string; alter: number };
console.log(user.name);

// DOM: Element könnte null sein
// const btn = document.getElementById("ok") as HTMLButtonElement;

// "!" – Non-null Assertion
function erste(arr: number[]) {
  return arr[0]!;  // ich versichere: nicht undefined
}

// "satisfies" – prüfen ohne zu verengen
const config = {
  port: 3000,
  host: "localhost"
} satisfies Record<string, string | number>;

console.log(config.port + 1);  // Typ bleibt number!
console.log(erste([10, 20]));
Rechts · Warnung
Sparsam einsetzen

Assertions schalten Prüfungen aus. Wenn du falsch liegst, crasht dein Programm zur Laufzeit.

Frag dich: Geht es nicht auch mit einem Type Guard?

Konsolen-Output
Anna
3001
10
Teil III

Die fortgeschrittenen Konzepte

Jetzt wird es interessant. Hier passiert die Magie von TypeScript — Typen werden zu einer eigenen kleinen Sprache, in der man rechnen, transformieren und schliessen kann.

17Generics — fortgeschritten

Generics werden richtig mächtig mit Constraints (Einschränkungen), Defaults und mehreren Typ-Parametern.

Links · Erklärung
extends — Constraint

<T extends X> heisst: „T muss mindestens die Form von X haben."

keyof als Constraint

K extends keyof T garantiert: K ist ein gültiger Property-Key von T.

Default-Typ

Mit <T = string> bekommt der Parameter einen Default, falls er nicht übergeben wird.

// Constraint: T muss eine Länge haben
function längste<T extends { length: number }>(
  a: T, b: T
): T {
  return a.length >= b.length ? a : b;
}

console.log(längste("hello", "hi"));
console.log(längste([1, 2, 3], [9]));

// keyof + zwei Typ-Parameter: typsicheres get()
function getProp<T, K extends keyof T>(
  obj: T, key: K
): T[K] {
  return obj[key];
}

const u = { name: "Anna", alter: 29 };
console.log(getProp(u, "name"));
console.log(getProp(u, "alter"));
// getProp(u, "xyz");  ✗ Fehler – nicht in keyof

// Default-Typ
interface Response<T = unknown> {
  ok: boolean;
  data: T;
}

const r: Response<number[]> = { ok: true, data: [1, 2] };
console.log(r.data.length);
Rechts · Output erklärt

"hello" hat 5 Zeichen, "hi" nur 2 → "hello".

Bei den Arrays: 3 > 1 → [1,2,3].

Bei getProp: der Rückgabetyp T[K] ist exakt der Typ des angefragten Felds — bei "name" string, bei "alter" number.

Konsolen-Output
hello
[ 1, 2, 3 ]
Anna
29

18Utility Types

TypeScript bringt eine Bibliothek mit „Werkzeug-Typen" mit — sie transformieren bestehende Typen in neue. Diese sind Brot & Butter im Alltag.

Links · Erklärung
Partial<T>

Macht alle Felder optional.

Required<T>

Macht alle Felder Pflicht.

Readonly<T>

Alle Felder werden unveränderbar.

Pick<T, K>

Wählt nur die angegebenen Felder aus.

Omit<T, K>

Das Gegenteil: lässt die angegebenen Felder weg.

interface User {
  id: number;
  name: string;
  email: string;
  passwort: string;
}

// Update-Payload: alles optional
type UserUpdate = Partial<User>;
const update: UserUpdate = { name: "Anna Neu" };

// Öffentlich: ohne Passwort
type PublicUser = Omit<User, "passwort">;

// Login: nur diese Felder
type Login = Pick<User, "email" | "passwort">;

// Record: Map mit festen Keys
type Rolle = "admin" | "user" | "gast";
const rechte: Record<Rolle, number> = {
  admin: 100,
  user: 50,
  gast: 10
};

const pub: PublicUser = {
  id: 1, name: "Anna", email: "a@x.de"
};

console.log(update);
console.log(pub);
console.log(rechte.admin);
Rechts · Weitere
Mehr Utility Types

NonNullable<T> — entfernt null/undefined

ReturnType<F> — der Rückgabetyp einer Funktion

Parameters<F> — Tuple der Parameter

Awaited<P> — der „ausgepackte" Promise-Typ

Readonly<T> — alle Felder readonly

Konsolen-Output
{ name: 'Anna Neu' }
{ id: 1, name: 'Anna', email: 'a@x.de' }
100

ReturnType & Parameters in Action

Links · Erklärung

typeof funktion gibt den Funktionstyp.

ReturnType<...> extrahiert daraus den Rückgabetyp.

So bleibt der abgeleitete Typ automatisch synchron mit der Funktion — keine Doppelpflege. 

function erstelleUser(name: string, alter: number) {
  return { id: Math.random(), name, alter, aktiv: true };
}

type User   = ReturnType<typeof erstelleUser>;
type Params = Parameters<typeof erstelleUser>;

const args: Params = ["Anna", 29];
const u: User = erstelleUser(...args);

console.log(u.name, u.aktiv);
Rechts · Wow-Effekt

Du hast die Typen User und Params nirgends von Hand definiert — sie werden vollständig aus der Funktion abgeleitet.

Ändert sich die Funktion, ändern sich die Typen mit.

Konsolen-Output
Anna true

19Mapped Types

Mapped Types erzeugen neue Typen, indem sie über die Properties eines bestehenden Typs iterieren — wie Array.map, nur auf Typ-Ebene.

Links · Erklärung
Die Syntax

{ [K in keyof T]: ... } heisst: „für jeden Key K aus T, erzeuge ein Feld mit dem angegebenen Typ."

Modifier-Tricks

+? macht optional, -? macht Pflicht.
+readonly macht readonly, -readonly entfernt es. 

type User = {
  id: number;
  name: string;
  email: string;
};

// Eigenes Partial
type MeinPartial<T> = {
  [K in keyof T]?: T[K];
};

// Alles zu string
type Stringify<T> = {
  [K in keyof T]: string;
};

// Readonly + optional
type Draft<T> = {
  readonly [K in keyof T]?: T[K];
};

const p: MeinPartial<User> = { name: "Anna" };
const s: Stringify<User> = {
  id: "1", name: "Anna", email: "a@x.de"
};

console.log(p);
console.log(s);
Rechts · Key Remapping
Keys umbenennen

Mit as kannst du im Mapped Type den Key transformieren:

type Getters<T> = {
  [K in keyof T as
    `get${Capitalize<string & K>}`
  ]: () => T[K];
};

Aus name wird getName.

Konsolen-Output
{ name: 'Anna' }
{ id: '1', name: 'Anna', email: 'a@x.de' }

20Conditional Types

Bedingungen auf Typ-Ebene: T extends U ? X : Y. Damit kannst du je nach Eingabe-Typ unterschiedliche Ergebnisse zurückgeben — die Basis vieler Utility Types.

Links · Erklärung
extends als Frage

„Ist T zuweisbar zu U?" — wenn ja, nimm X, sonst Y.

infer

Das absolute Power-Feature: infer X lässt TS einen Typ aus einer Stelle extrahieren.

So funktionieren ReturnType, Awaited, Parameters & Co. unter der Haube.

// Einfache Bedingung
type IstString<T> = T extends string ? true : false;

type A = IstString<"hallo">;  // true
type B = IstString<42>;       // false

// Mit infer: Element-Typ eines Arrays holen
type ElementOf<T> = T extends (infer E)[] ? E : never;

type C = ElementOf<string[]>;       // string
type D = ElementOf<number[]>;       // number

// Eigenes ReturnType
type MyReturn<F> = F extends (...a: any[]) => infer R
  ? R
  : never;

function hi() { return "hallo"; }
type HiR = MyReturn<typeof hi>; // string

// Demo zur Laufzeit (zeigt die Funktion)
const x: HiR = hi();
console.log(x, typeof x);
Rechts · Distributiv
Union verteilt sich

Bei Conditional Types verteilt sich eine Union automatisch:

IstString<"a" | 1>

wird zu

IstString<"a"> | IstString<1>

also true | false = boolean.

Konsolen-Output
hallo string

21Template Literal Types

Wie Template-Strings in JS — nur dass sie Typen zusammenbauen. Erlaubt sehr präzise Restriktionen, z.B. für CSS-Werte, Event-Namen oder API-Routen.

Links · Erklärung
Strings auf Typ-Ebene bauen

Du kombinierst Literal-Types mit Template-Backticks. Das Ergebnis ist eine genaue Vorgabe für erlaubte Strings.

Kombinierbar mit Utilities

Uppercase, Lowercase, Capitalize und Uncapitalize sind eingebaute String-Manipulationen auf Typ-Ebene.

type Farbe    = "rot" | "grün" | "blau";
type Helligkeit = "hell" | "dunkel";

// Kombiniert: "hell-rot" | "hell-grün" ...
type FarbCode = `${Helligkeit}-${Farbe}`;

const c1: FarbCode = "hell-rot";     // ✓
// const c2: FarbCode = "hell-lila";  ✗ Fehler

// Event-Handler-Namen
type EventName = "click" | "hover" | "submit";
type Handler<E extends string> = `on${Capitalize<E>}`;

type H = Handler<EventName>;
// "onClick" | "onHover" | "onSubmit"

const handler: H = "onClick";
console.log(c1, handler);

// API-Route
type Route = `/api/${string}`;
const r: Route = "/api/users/42";
console.log(r);
Rechts · Anwendung
Praxisbeispiele

CSS-Längen: `${number}px` | `${number}%`

Redux-Actions: `user/${string}`

Storage-Keys: `cache:${string}`

Sehr beliebt in Bibliotheken wie tRPC oder Drizzle.

Konsolen-Output
hell-rot onClick
/api/users/42

22Discriminated Unions

Ein Pattern, das in TS-Code überall auftaucht: mehrere Objekt-Typen mit einem gemeinsamen Diskriminator-Feld, das den Typ eindeutig identifiziert.

Links · Erklärung
Das Diskriminator-Feld

Üblicherweise kind, type oder status. Jedes Mitglied der Union setzt es auf einen anderen Literal-String.

Narrowing via switch

Im switch auf den Diskriminator verengt TS automatisch — innerhalb jedes case kennt es die exakte Form.

Exhaustiveness mit never

Der default-Zweig fängt Fälle ab, die du vergessen hast — der Compiler warnt.

type Form =
  | { kind: "kreis";   radius: number }
  | { kind: "quadrat"; seite: number }
  | { kind: "rechteck"; b: number; h: number };

function fläche(f: Form): number {
  switch (f.kind) {
    case "kreis":
      return Math.PI * f.radius ** 2;
    case "quadrat":
      return f.seite ** 2;
    case "rechteck":
      return f.b * f.h;
    default:
      const _e: never = f;  // Vollständigkeit!
      return _e;
  }
}

console.log(fläche({ kind: "kreis",    radius: 5 }));
console.log(fläche({ kind: "quadrat",  seite:  4 }));
console.log(fläche({ kind: "rechteck", b: 3, h: 7 }));
Rechts · Beliebtes Muster
API-Responses
type Result<T> =
  | { ok: true; data: T }
  | { ok: false; error: string };

Im Aufrufer prüfst du if (res.ok) — TS weiss dann, dass data existiert.

Konsolen-Output
78.53981633974483
16

23keyof & typeof

Zwei Typ-Operatoren, die du ständig brauchst: keyof liefert die Keys eines Typs als Union, typeof macht aus einem Wert einen Typ.

Links · Erklärung
keyof T

Ergibt die Union aller Property-Namen von T als String-Literals.

typeof variable

Liest den Typ einer Variablen aus — sehr praktisch, um sich keine Typen doppelt aufschreiben zu müssen.

Kombiniert

typeof obj + keyof typeof obj ergibt eine typsichere Liste der Schlüssel.

const user = {
  name: "Anna",
  alter: 29,
  email: "a@x.de"
};

type User    = typeof user;
// { name: string; alter: number; email: string }

type UserKey = keyof User;
// "name" | "alter" | "email"

function log<K extends UserKey>(k: K): User[K] {
  return user[k];
}

console.log(log("name"));
console.log(log("alter"));
// log("xyz");  ✗ – nicht in keyof

// "as const" friert Werte ein
const rollen = ["admin", "user", "gast"] as const;
type Rolle = (typeof rollen)[number];
// "admin" | "user" | "gast"

const r: Rolle = "admin";
console.log(r);
Rechts · Magie
as const

Ohne as const wäre rollen ein string[] — der Index-Typ wäre nur string.

Mit as const werden die Werte readonly und behalten ihre exakten Literal-Typen.

Dann ergibt (typeof rollen)[number] die präzise Union.

Konsolen-Output
Anna
29
admin

24Decorators

Decorators sind Funktionen, die Klassen, Methoden oder Felder „dekorieren" — also ihr Verhalten erweitern. Bekannt aus Angular, NestJS und MobX.

Hinweis

Seit TypeScript 5.0 sind Standard-konforme Decorators (TC39 Stage 3) verfügbar. Aktiviere sie über "experimentalDecorators" in tsconfig oder nutze die neue Syntax direkt — Frameworks setzen oft noch auf die alte Variante.

Links · Erklärung
Methoden-Decorator

Ein Decorator, der eine Methode wrappt: vorher und nachher loggen, Argumente prüfen, Performance messen — du fügst Logik hinzu, ohne die Methode selbst zu ändern.

Anwendung

Mit @decorator über der Methode angeben.

// Methoden-Decorator (Stage 3 Syntax)
function logged<This, Args extends any[], Ret>(
  target: (this: This, ...a: Args) => Ret,
  ctx: ClassMethodDecoratorContext
) {
  return function (this: This, ...args: Args): Ret {
    console.log(`→ ${String(ctx.name)}(${args})`);
    const r = target.call(this, ...args);
    console.log(`← ${r}`);
    return r;
  };
}

class Rechner {
  @logged
  addiere(a: number, b: number) {
    return a + b;
  }
}

const r = new Rechner();
r.addiere(2, 3);
r.addiere(10, 5);
Rechts · Was passiert

Bei jedem Aufruf von addiere wird die echte Methode automatisch von einem Wrapper umgeben — der vorher die Argumente loggt und nachher das Ergebnis.

Dieselbe Idee steckt hinter @Component in Angular oder @Controller in NestJS.

Konsolen-Output
→ addiere(2,3)
← 5
→ addiere(10,5)
← 15

25Module

TypeScript nutzt das normale ES-Modul-System: export stellt etwas bereit, import holt es. Pro Datei = pro Modul.

Links · Erklärung
Named Exports

Mehrere Exports pro Datei, beim Import in geschweiften Klammern.

Default Export

Genau ein Standard-Export pro Datei, beim Import frei benennbar.

Type-only Imports

import type importiert nur den Typ — der Compiler entfernt die Zeile komplett aus dem JS-Output.

// mathe.ts
export function add(a: number, b: number) {
  return a + b;
}

export const PI = 3.14159;

export type Vektor = { x: number; y: number };

export default class Rechner {
  summe(a: number, b: number) { return a + b; }
}


// app.ts
import Rechner, { add, PI } from "./mathe";
import type { Vektor } from "./mathe";

const v: Vektor = { x: 1, y: 2 };

console.log(add(2, 3));
console.log(PI);
console.log(new Rechner().summe(10, 20));
console.log(v);
Rechts · Best Practice
Named > Default

Bevorzuge Named Exports — sie sind durchsuchbar, einheitlich benannt und beim Refactoring sicherer.

Barrel Files

Eine index.ts, die alles aus einem Ordner re-exportiert, vereinfacht Imports:

import { X, Y } from "./module";
