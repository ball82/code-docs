Teil I

Die Grundlagen

Was ist HTML, wie sieht ein Dokument aus, und welche Tags brauchst du für Text, Links, Bilder, Listen, Tabellen und Formulare?

01 Was ist HTML?

HTML (HyperText Markup Language) ist die Struktur-Sprache des Webs. Jeder Inhalt, den du im Browser siehst — Text, Bilder, Buttons, Videos — steckt in HTML-Tags. HTML beschreibt was auf der Seite ist (Überschrift, Absatz, Link), nicht wie es aussieht (das macht CSS).

  • Tags — Anweisungen in spitzen Klammern: <p>Text</p>
  • Attribute — Zusatzinfos im öffnenden Tag: <a href="...">
  • Verschachtelt — Tags enthalten andere Tags = DOM-Baum
  • Living Standard — HTML wird laufend aktualisiert (kein "HTML6")

02 Das Grundgerüst

Jede HTML-Datei folgt dem gleichen Aufbau: DOCTYPE, <html>, <head> (Metadaten) und <body> (sichtbarer Inhalt).

Links · Aufbau
<!DOCTYPE html>

Sagt dem Browser: "Dies ist modernes HTML." Immer erste Zeile.

<html lang="de">

Wurzelelement. lang hilft Screenreadern und Google.

<head>

Unsichtbar: Titel, Zeichensatz, Viewport, CSS-Links, Favicons.

<body>

Alles, was der User sieht und mit dem er interagiert.

index.html
<!DOCTYPE html>
<html lang="de">
<head>
  <meta charset="UTF-8">
  <meta name="viewport"
        content="width=device-width,
                 initial-scale=1.0">
  <title>Meine Seite</title>
</head>
<body>
  <h1>Hallo Welt!</h1>
  <p>Mein erstes HTML-Dokument.</p>
</body>
</html>
Rechts · Tipps
charset UTF-8

Immer setzen — sonst Zeichensalat bei ä, ö, ü, é, etc.

viewport

Ohne das ist deine Seite auf dem Handy winzig.

title

Erscheint im Browser-Tab und in Google-Ergebnissen.

index.html

Hallo Welt!

Mein erstes HTML-Dokument.

03 Text-Elemente

Überschriften (<h1>–<h6>), Absätze (<p>), Hervorhebungen (<strong>, <em>), Zeilenumbrüche (<br>) und thematische Trennlinien (<hr>).

Links · Tags
h1–h6

Hierarchische Überschriften. h1 = wichtigste, nur einmal pro Seite.

p

Absatz — das Standard-Element für Fliesstext.

strong / em

strong = wichtig (fett). em = betont (kursiv). Nicht für Styling — dafür CSS.

br / hr

Zeilenumbruch / horizontale Linie. Selbstschliessend.

text.html
<h1>Hauptüberschrift</h1>
<h2>Unterkapitel</h2>
<h3>Abschnitt</h3>

<p>Das ist ein <strong>wichtiger</strong>
   Absatz mit <em>Betonung</em>.</p>

<p>Zeile eins<br>
   Zeile zwei</p>

<hr>

<p>Weitere Tags:
  <small>klein</small>,
  <mark>markiert</mark>,
  <del>gelöscht</del>,
  <ins>eingefügt</ins>,
  <code>Code</code>
</p>
Rechts · Hinweis
Semantik zählt

<strong> heisst "wichtig" für Screenreader. <b> ist nur visuell fett — ohne Bedeutung.

Nur ein h1

Google und Screenreader erwarten genau eine h1 pro Seite.

mark

Highlight — ideal für Suchergebnisse.

text.html

Hauptüberschrift

Unterkapitel

Abschnitt

Das ist ein wichtiger Absatz mit Betonung.

Zeile eins
Zeile zwei

Weitere Tags: klein, markiert, gelöscht, eingefügt, Code

04 Links & Navigation

Der <a>-Tag macht das Web zum Web — er verbindet Seiten miteinander. Das href-Attribut sagt, wohin es geht.

Links · Arten
Extern

Volle URL: https://...

Intern

Relativer Pfad: about.html, ./kontakt

Anker

#id — springt zu einem Element auf der gleichen Seite.

E-Mail / Telefon

mailto: und tel:-Protokolle.

links.html
<!-- Externe Links -->
<a href="https://example.com">
  Externe Seite
</a>

<a href="https://example.com"
   target="_blank"
   rel="noopener noreferrer">
  In neuem Tab
</a>

<!-- Interne Links -->
<a href="about.html">Über uns</a>
<a href="#kontakt">Zum Kontakt</a>

<!-- Spezial-Protokolle -->
<a href="mailto:hi@example.com">Mail</a>
<a href="tel:+41791234567">Anrufen</a>

<!-- Download -->
<a href="report.pdf" download>PDF laden</a>
Rechts · Sicherheit
target="_blank"

Öffnet neuen Tab. Immer mit rel="noopener noreferrer" — verhindert Sicherheitslücken.

download

Erzwingt Download statt Navigation.

Keine leeren href

href="#" oder href="" vermeiden — erzeugt unnötige Navigations-Events.

05 Bilder & Medien

<img> für Bilder, <video> und <audio> für Medien. Alle drei sind selbstschliessend oder Container-Elemente mit Fallback-Inhalt.

Links · Elemente
img

Selbstschliessend. src = Quelle, alt = Beschreibung (Pflicht!).

figure + figcaption

Bild mit Beschriftung — semantisch sauber.

video / audio

Native Player. controls zeigt Play/Pause-Leiste.

medien.html
<img src="katze.jpg"
     alt="Eine orange Katze auf dem Sofa"
     width="600"
     height="400"
     loading="lazy">

<figure>
  <img src="chart.png" alt="Q3 Umsatz">
  <figcaption>Umsatzentwicklung Q3</figcaption>
</figure>

<video controls width="640">
  <source src="clip.mp4" type="video/mp4">
  Dein Browser unterstützt kein Video.
</video>

<audio controls>
  <source src="song.mp3" type="audio/mpeg">
</audio>
Rechts · Tipps
alt-Text

Beschreibt, was auf dem Bild zu sehen ist. Leer lassen (alt="") nur bei dekorativen Bildern.

width + height

Verhindert Layout-Shifts beim Laden — Browser reserviert den Platz.

loading="lazy"

Bild wird erst geladen, wenn es in den Viewport scrollt.

06 Listen

Ungeordnet (<ul>), geordnet (<ol>) und Definitionslisten (<dl>). Listen sind auch die Basis für Navigation-Menüs.

Links · Typen
ul

Aufzählung ohne Reihenfolge — Punkte.

ol

Nummerierte Liste — Reihenfolge zählt.

dl / dt / dd

Begriffe (dt) mit Definitionen (dd). Ideal für FAQs, Glossare.

listen.html
<ul>
  <li>Äpfel</li>
  <li>Bananen</li>
  <li>Kirschen</li>
</ul>

<ol start="3">
  <li>Dritter Schritt</li>
  <li>Vierter Schritt</li>
</ol>

<dl>
  <dt>HTML</dt>
  <dd>HyperText Markup Language</dd>
  <dt>CSS</dt>
  <dd>Cascading Style Sheets</dd>
</dl>
Rechts · Notiz
Verschachtelung

Listen in Listen = Untermenüs. <li> kann eine eigene <ul> enthalten.

start / reversed

<ol start="5"> zählt ab 5. <ol reversed> zählt rückwärts.

Navigation

<nav><ul>...</ul></nav> = semantisch korrekte Navigation.

07 Tabellen

Tabellen sind für tabellarische Daten — nicht für Layout! Mit <thead>, <tbody> und <th> wird die Struktur klar.

Links · Aufbau
table

Container für die gesamte Tabelle.

thead / tbody / tfoot

Logische Gruppen: Kopf, Körper, Fuss.

th vs td

th = Header-Zelle (fett, zentriert). td = Daten-Zelle.

tabelle.html
<table>
  <thead>
    <tr>
      <th>Name</th>
      <th>Alter</th>
      <th>Stadt</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Mara</td>
      <td>28</td>
      <td>Zürich</td>
    </tr>
    <tr>
      <td>Lukas</td>
      <td>34</td>
      <td>Bern</td>
    </tr>
  </tbody>
</table>
Rechts · Tipp
colspan / rowspan

<td colspan="2"> — Zelle erstreckt sich über 2 Spalten.

caption

<caption>Mitarbeiterliste</caption> als erstes Kind — beschreibt die Tabelle.

scope

<th scope="col"> verbessert Accessibility für Screenreader.

tabelle.html
Name Alter Stadt
Mara 28 Zürich
Lukas 34 Bern

08 Formulare — Grundlagen

<form> sammelt User-Eingaben. Jedes Eingabefeld braucht ein <label> — verbunden über for/id.

Links · Elemente
form

Container. action = Ziel-URL, method = GET oder POST.

input

Das Schweizer Taschenmesser: type="text", email, password, number, date, checkbox, radio, ...

label

Klick auf Label = Fokus aufs Feld. Pflicht für Accessibility.

button

type="submit" (Standard) sendet das Formular.

form.html
<form action="/api/register" method="POST">
  <label for="name">Name</label>
  <input id="name" type="text"
         placeholder="Max Muster"
         required>

  <label for="email">E-Mail</label>
  <input id="email" type="email" required>

  <label for="pw">Passwort</label>
  <input id="pw" type="password"
         minlength="8" required>

  <label>
    <input type="checkbox" required>
    AGB akzeptieren
  </label>

  <button type="submit">Registrieren</button>
</form>
Rechts · Validierung
required

Feld muss ausgefüllt sein — Browser zeigt Fehlermeldung.

type="email"

Browser prüft automatisch auf gültige E-Mail.

minlength / maxlength

Längen-Beschränkung direkt im HTML.

pattern

Eigene Regex: pattern="[0-9]{5}" = 5 Ziffern.

09 Semantische Elemente

Semantische Tags geben dem Inhalt Bedeutung — nicht nur Aussehen. <header>, <nav>, <main>, <article>, <section>, <aside>, <footer>.

Links · Tags
header

Kopfbereich — Logo, Navigation, Titel.

nav

Navigations-Block — Hauptmenü, Breadcrumbs.

main

Der einzigartige Hauptinhalt. Nur einmal pro Seite.

article / section

article = eigenständiger Inhalt (Blogpost). section = thematischer Abschnitt.

aside

Sidebar, verwandter Content, Werbung.

footer

Fussbereich — Copyright, Links, Kontakt.

layout.html
<body>
  <header>
    <h1>Mein Blog</h1>
    <nav>
      <a href="/">Home</a>
      <a href="/about">Über</a>
    </nav>
  </header>

  <main>
    <article>
      <h2>Erster Post</h2>
      <p>Inhalt...</p>
      <time datetime="2026-06-02">
        2. Juni 2026
      </time>
    </article>
    <aside>
      <h3>Kategorien</h3>
      <ul>...</ul>
    </aside>
  </main>

  <footer>
    <p>&copy; 2026</p>
  </footer>
</body>
Rechts · Warum?
SEO

Google versteht die Seitenstruktur besser.

Accessibility

Screenreader können direkt zum main oder nav springen.

time

datetime-Attribut = maschinenlesbares Datum.

div = letzter Ausweg

Nur <div> nutzen, wenn kein semantisches Element passt.

10 Formulare — Fortgeschritten

<select>, <textarea>, <fieldset>, <datalist> und die ganzen Input-Typen, die dir Validierung gratis geben.

Links · Elemente
select + option

Dropdown-Auswahl. multiple = Mehrfachauswahl.

textarea

Mehrzeiliges Textfeld. rows/cols für Grösse.

fieldset + legend

Gruppiert Felder visuell und semantisch.

datalist

Autocomplete-Vorschläge für ein Input-Feld.

form-adv.html
<fieldset>
  <legend>Persönliche Daten</legend>

  <label for="land">Land</label>
  <select id="land">
    <option value="">Bitte wählen</option>
    <option value="ch">Schweiz</option>
    <option value="de">Deutschland</option>
    <option value="at">Österreich</option>
  </select>

  <label for="bio">Bio</label>
  <textarea id="bio" rows="4"
    maxlength="500"
    placeholder="Erzähl von dir..."></textarea>

  <label for="city">Stadt</label>
  <input id="city" list="staedte">
  <datalist id="staedte">
    <option value="Zürich">
    <option value="Bern">
    <option value="Basel">
  </datalist>

  <label for="dob">Geburtsdatum</label>
  <input id="dob" type="date">

  <input type="range" min="0" max="100" value="50">
  <input type="color" value="#e44d26">
</fieldset>
Rechts · Tipps
Input-Typen

date, time, color, range, search, url, tel, file — Browser liefert native UI.

autocomplete

autocomplete="email" füllt gespeicherte Daten automatisch ein.

optgroup

Gruppiert Optionen in einem Select: <optgroup label="Europa">.

11 Meta-Tags & SEO

Was im <head> steht, sehen User nicht direkt — aber Google, Social Media und Browser brauchen es dringend.

Links · Tags
title

Browser-Tab + Google-Snippet. 50–60 Zeichen optimal.

meta description

Google-Snippet. 150–160 Zeichen.

Open Graph

og:title, og:image, og:description — für Social-Media-Previews.

favicon

Das kleine Icon im Tab.

head.html
<head>
  <meta charset="UTF-8">
  <meta name="viewport"
        content="width=device-width, initial-scale=1">
  <title>Mara's Portfolio — UX Design</title>
  <meta name="description"
        content="UX-Designerin aus Zürich.
                 Projekte, Case Studies, Kontakt.">

  <!-- Open Graph (Social Media) -->
  <meta property="og:title" content="Mara's Portfolio">
  <meta property="og:image" content="https://...">
  <meta property="og:type" content="website">

  <!-- Favicon -->
  <link rel="icon" href="/favicon.svg" type="image/svg+xml">

  <!-- CSS -->
  <link rel="stylesheet" href="style.css">
</head>
Rechts · Notiz
robots

<meta name="robots" content="noindex"> — Seite nicht indexieren.

canonical

<link rel="canonical" href="..."> — vermeidet Duplicate Content.

theme-color

<meta name="theme-color" content="#e44d26"> — färbt Browser-UI auf Mobile.

12 Inline vs. Block

Jedes HTML-Element ist entweder Block (nimmt volle Breite, neue Zeile) oder Inline (fliesst im Text mit). Dieses Konzept bestimmt, wie Elemente sich verhalten.

Links · Unterschied
Block

div, p, h1–h6, section, ul, form, header, footer. Nehmen die ganze Breite, erzeugen neue Zeile.

Inline

span, a, strong, em, img, code, br. Fliessen neben anderen Elementen.

inline-block.html
<!-- Block: eigene Zeile -->
<div>Ich bin ein Block.</div>
<div>Ich auch — neue Zeile.</div>

<!-- Inline: im Text -->
<p>
  Das ist <strong>fett</strong> und
  <a href="#">ein Link</a>
  — alles in einer Zeile.
</p>

<!-- div = generischer Block-Container -->
<div class="card">
  <h3>Titel</h3>
  <p>Inhalt</p>
</div>

<!-- span = generischer Inline-Container -->
<p>Preis: <span class="price">CHF 29.90</span></p>
Rechts · Regel
Goldene Regel

Block-Elemente dürfen Inline-Elemente enthalten. Inline-Elemente sollten keine Block-Elemente enthalten.

Ausnahme

<a> darf Blocks umschliessen (z. B. eine ganze Card klickbar machen).

13 Globale Attribute

Bestimmte Attribute funktionieren auf jedem HTML-Element — id, class, style, data-*, hidden, title und die aria-*-Attribute.

Links · Attribute
id

Einzigartig pro Seite. Für Anker-Links, Labels, JS.

class

Mehrere möglich, getrennt durch Leerzeichen. Für CSS-Styling.

data-*

Eigene Daten am Element speichern — in JS via dataset auslesen.

hidden

Element ausblenden, ohne es zu löschen.

attribute.html
<div id="hero"
     class="section full-width dark"
     data-page="home"
     data-version="2">
  ...
</div>

<p title="Tooltip beim Hover">
  Fahr über mich.
</p>

<p hidden>Ich bin unsichtbar.</p>

<p contenteditable="true">
  Klick und bearbeite mich!
</p>

<div tabindex="0">
  Ich bin per Tab erreichbar.
</div>

<script>
  const el = document.getElementById('hero');
  console.log(el.dataset.page);    // "home"
  console.log(el.dataset.version); // "2"
</script>
Rechts · Notiz
data-* → dataset

data-user-id="42" wird zu el.dataset.userId (camelCase).

contenteditable

Macht jedes Element editierbar — Basis für Rich-Text-Editoren.

tabindex

0 = in Tab-Reihenfolge. -1 = nur per JS fokussierbar.

Console
home
2

14 Einbetten — iframe & mehr

<iframe> bettet eine fremde Seite ein — YouTube-Videos, Google Maps, etc. Mit sandbox und allow steuerst du die Berechtigungen.

Links · Elemente
iframe

Bettet eine externe Seite ein. src = URL, width/height für Grösse.

sandbox

Schränkt ein, was der iframe darf — Scripts, Forms, Navigation.

loading="lazy"

Wie bei Bildern: erst laden, wenn sichtbar.

embed.html
<!-- YouTube-Video -->
<iframe
  src="https://www.youtube.com/embed/dQw4w9"
  width="560" height="315"
  loading="lazy"
  allow="accelerometer; autoplay;
         encrypted-media; picture-in-picture"
  allowfullscreen>
</iframe>

<!-- Google Maps -->
<iframe
  src="https://maps.google.com/maps?q=Zürich&output=embed"
  width="600" height="400"
  loading="lazy"
  sandbox="allow-scripts">
</iframe>
Rechts · Sicherheit
sandbox

Ohne Wert = alles blockiert. Mit allow-scripts erlaubst du JS.

Performance

Jeder iframe = eigener Browser-Context. Viele iframes = langsam.

Responsive

CSS aspect-ratio: 16/9 + width: 100% macht iframes responsive.

15 Responsive Bilder

Mit <picture>, srcset und sizes lieferst du das richtige Bild für jede Bildschirmgrösse — weniger Daten auf dem Handy, scharfe Bilder auf Retina.

Links · Techniken
srcset

Mehrere Bild-Versionen mit Breiten-Deskriptor (400w, 800w).

sizes

Sagt dem Browser, wie breit das Bild im Layout sein wird.

picture + source

Verschiedene Bilder je nach Media-Query oder Format (WebP, AVIF).

responsive-img.html
<!-- srcset + sizes -->
<img
  srcset="foto-400.jpg 400w,
          foto-800.jpg 800w,
          foto-1200.jpg 1200w"
  sizes="(max-width: 600px) 100vw,
         (max-width: 1200px) 50vw,
         600px"
  src="foto-800.jpg"
  alt="Landschaft">

<!-- picture: Format-Fallback -->
<picture>
  <source srcset="foto.avif" type="image/avif">
  <source srcset="foto.webp" type="image/webp">
  <img src="foto.jpg" alt="Landschaft">
</picture>

<!-- picture: Art Direction -->
<picture>
  <source media="(max-width: 640px)"
          srcset="hero-mobile.jpg">
  <img src="hero-desktop.jpg" alt="Hero">
</picture>
Rechts · Tipp
AVIF > WebP > JPEG

AVIF ist am kleinsten, WebP gut unterstützt, JPEG als Fallback.

Art Direction

Anderer Bildausschnitt auf dem Handy — nicht nur kleiner, sondern anders zugeschnitten.

Immer alt!

alt bleibt Pflicht — auch bei responsive Bildern.

16 Details & Dialog

Interaktive Elemente ohne JavaScript: <details> für Aufklapp-Bereiche (Accordions, FAQs), <dialog> für modale Popups.

Links · Elemente
details + summary

Klick auf summary klappt den Rest auf/zu. Kein JS nötig.

open

Attribut open = initial aufgeklappt.

dialog

Modaler oder nicht-modaler Dialog. showModal() per JS öffnen.

details-dialog.html
<!-- Accordion / FAQ -->
<details>
  <summary>Was kostet der Versand?</summary>
  <p>Kostenlos ab CHF 50, sonst CHF 5.90.</p>
</details>

<details open>
  <summary>Rückgabe?</summary>
  <p>30 Tage kostenlose Rückgabe.</p>
</details>

<!-- Dialog (modal) -->
<dialog id="confirm">
  <h2>Bist du sicher?</h2>
  <p>Diese Aktion kann nicht rückgängig
     gemacht werden.</p>
  <button onclick="confirm.close()">OK</button>
</dialog>

<button onclick="confirm.showModal()">
  Löschen
</button>
Rechts · Notiz
Accessibility

Beide Elemente sind von Haus aus accessible — Fokus, Keyboard, Screenreader.

::backdrop

CSS-Pseudo-Element für den dunklen Hintergrund hinter einem Modal.

name-Attribut

<details name="faq"> — nur eines der Gruppe ist gleichzeitig offen (Accordion-Verhalten).

17 Template & Slot

<template> enthält HTML, das nicht gerendert wird — du klonst es per JavaScript. <slot> ist der Platzhalter in Web Components für Kind-Inhalte.

Links · Konzept
template

Inert — Browser parst es, rendert es aber nicht. Perfekt für wiederholte Strukturen.

Klonen

template.content.cloneNode(true) erzeugt eine Kopie.

slot

Wird in Web Components genutzt — siehe Kapitel 20.

template.html
<template id="card-tpl">
  <div class="card">
    <h3 class="title"></h3>
    <p class="body"></p>
  </div>
</template>

<div id="container"></div>

<script>
  const tpl = document.getElementById('card-tpl');
  const data = [
    { title: 'Karte 1', body: 'Inhalt A' },
    { title: 'Karte 2', body: 'Inhalt B' }
  ];

  for (const item of data) {
    const clone = tpl.content.cloneNode(true);
    clone.querySelector('.title').textContent = item.title;
    clone.querySelector('.body').textContent = item.body;
    document.getElementById('container').append(clone);
  }
</script>
Rechts · Tipp
Warum template?

Kein Styling-Flash, keine unnötigen HTTP-Requests — alles inert bis zum Klonen.

Performance

Schneller als innerHTML für wiederholte Strukturen.

slot (Vorschau)

<slot name="header"> in einem Shadow-DOM = Platzhalter für Content.

18 Accessibility (ARIA)

Accessibility heisst: deine Seite funktioniert für alle — Screenreader, Tastatur-Navigation, Farbfehlsichtige. ARIA-Attribute ergänzen, was semantisches HTML nicht abdeckt.

Links · ARIA
role

Überschreibt die Rolle eines Elements: role="button", role="alert".

aria-label

Unsichtbare Beschriftung für Screenreader.

aria-hidden

Versteckt dekorative Elemente vor Screenreadern.

aria-live

Dynamische Updates vorlesen: "polite" oder "assertive".

a11y.html
<!-- Gutes Label -->
<button aria-label="Menü schliessen">
  ✕
</button>

<!-- Skip-Link -->
<a href="#main" class="skip-link">
  Zum Inhalt springen
</a>

<!-- Live-Region für Updates -->
<div aria-live="polite" id="status">
  3 Ergebnisse gefunden
</div>

<!-- Dekoratives Icon -->
<span aria-hidden="true">🎨</span>
<span>Design</span>

<!-- Formulare: aria-describedby -->
<input type="password"
       aria-describedby="pw-hint">
<p id="pw-hint">Mind. 8 Zeichen</p>
Rechts · Regeln
Erst semantisch

Nutze <button> statt <div role="button">. ARIA ist der Fallback, nicht der Standard.

Kontrast

Mindestens 4.5:1 für normalen Text (WCAG AA).

Keyboard

Alle interaktiven Elemente per Tab und Enter erreichbar?

19 Web Components

Eigene HTML-Tags bauen — mit Custom Elements, Shadow DOM und Templates. Framework-unabhängig, wiederverwendbar.

Links · Bausteine
Custom Element

Klasse von HTMLElement ableiten, mit customElements.define() registrieren.

Shadow DOM

Isolierter DOM-Baum — CSS und IDs "lecken" nicht nach aussen.

Lifecycle

connectedCallback, disconnectedCallback, attributeChangedCallback.

greeting-card.js
class GreetingCard extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: 'open' });
  }

  connectedCallback() {
    const name = this.getAttribute('name') ?? 'Welt';
    this.shadowRoot.innerHTML = `
      <style>
        :host { display: block; padding: 16px;
                border: 2px solid #e44d26;
                border-radius: 8px; }
        h2 { color: #e44d26; margin: 0; }
      </style>
      <h2>Hallo ${name}!</h2>
      <slot></slot>
    `;
  }
}

customElements.define('greeting-card', GreetingCard);

// Verwendung:
// <greeting-card name="Mara">
//   <p>Willkommen!</p>
// </greeting-card>
Rechts · Tipp
Naming

Custom Elements brauchen einen Bindestrich im Namen: my-card, nicht mycard.

:host

CSS-Selektor für das Custom Element selbst.

slot

Der <slot> rendert die Kind-Elemente des Custom Elements.

20 Canvas

<canvas> ist eine Pixel-Zeichenfläche. Du steuerst alles per JavaScript — Linien, Formen, Text, Bilder, Animationen.

Links · API
getContext('2d')

Holt den 2D-Zeichenkontext.

fillRect / strokeRect

Rechtecke füllen oder umranden.

arc / beginPath

Kreise und Pfade zeichnen.

fillText

Text aufs Canvas schreiben.

canvas.html
<canvas id="c" width="300" height="200">
  Fallback für alte Browser
</canvas>

<script>
  const ctx = document.getElementById('c')
    .getContext('2d');

  // Rechteck
  ctx.fillStyle = '#e44d26';
  ctx.fillRect(10, 10, 120, 80);

  // Kreis
  ctx.beginPath();
  ctx.arc(220, 100, 50, 0, Math.PI * 2);
  ctx.fillStyle = '#e8a64a';
  ctx.fill();

  // Text
  ctx.fillStyle = 'white';
  ctx.font = '20px sans-serif';
  ctx.fillText('Canvas!', 30, 55);
</script>
Rechts · Notiz
Canvas vs SVG

Canvas = Pixel (schnell für viele Objekte). SVG = Vektor (skaliert, einzeln anklickbar).

WebGL

getContext('webgl2') für 3D-Grafik.

Accessibility

Canvas ist für Screenreader unsichtbar — Fallback-Text im Tag oder ARIA nutzen.

21 SVG

Scalable Vector Graphics — XML-basierte Vektorgrafiken direkt im HTML. Perfekt für Icons, Logos, Charts — unendlich skalierbar, per CSS stylebar.

Links · Elemente
svg

Container. viewBox definiert das Koordinatensystem.

Formen

circle, rect, line, polygon, path.

CSS-styling

fill, stroke, stroke-width — alles per CSS steuerbar.

icon.html
<svg viewBox="0 0 100 100"
     width="80" height="80"
     xmlns="http://www.w3.org/2000/svg">

  <!-- Kreis -->
  <circle cx="50" cy="50" r="45"
    fill="#e44d26" stroke="#fff"
    stroke-width="3" />

  <!-- Text im SVG -->
  <text x="50" y="55"
    text-anchor="middle"
    fill="white"
    font-size="24"
    font-weight="bold">
    HTML
  </text>

</svg>

<!-- Oder als Bild -->
<img src="logo.svg" alt="Logo" width="64">
Rechts · Tipp
Inline vs img

Inline SVG = CSS/JS-Zugriff. <img src="x.svg"> = einfacher, aber kein Styling.

currentColor

fill="currentColor" — übernimmt die Text-Farbe des Elternelements.

Path

<path d="M10 10 L90 90"> — mächtigster SVG-Befehl.

23 Content Security

HTML-Attribute, die deine Seite und deine User schützen: sandbox, referrerpolicy, integrity, crossorigin.

Links · Attribute
rel="noopener"

Bei target="_blank" — verhindert Zugriff auf window.opener.

integrity

SRI-Hash für externe Scripts/Styles — Schutz vor CDN-Kompromittierung.

referrerpolicy

Steuert, welcher Referrer-Header gesendet wird.

security.html
<!-- SRI: Subresource Integrity -->
<script
  src="https://cdn.example.com/lib.js"
  integrity="sha384-abc123..."
  crossorigin="anonymous">
</script>

<!-- Sicherer Link -->
<a href="https://extern.com"
   target="_blank"
   rel="noopener noreferrer">
  Externe Seite
</a>

<!-- CSP via Meta-Tag -->
<meta http-equiv="Content-Security-Policy"
      content="default-src 'self';
               img-src 'self' https:;
               script-src 'self'">
Rechts · Wichtig
CSP

Content Security Policy — definiert, was geladen werden darf. Am besten als HTTP-Header.

XSS-Prävention

Nie User-Input in innerHTML setzen. textContent ist safe.

24 Performance & Loading

HTML-Attribute, die deine Seite schneller laden lassen: loading, fetchpriority, preload, prefetch, dns-prefetch, defer, async.

Links · Strategien
loading="lazy"

Bilder und iframes erst laden, wenn sie sichtbar werden.

fetchpriority

"high" für LCP-Bild, "low" für unwichtiges.

preload / prefetch

Ressourcen vorladen (jetzt nötig vs. bald nötig).

defer / async

Scripts nicht-blockierend laden.

performance.html
<head>
  <!-- Fonts vorladen -->
  <link rel="preload" href="font.woff2"
        as="font" type="font/woff2" crossorigin>

  <!-- DNS vorab auflösen -->
  <link rel="dns-prefetch" href="https://api.example.com">

  <!-- Nächste Seite vorladen -->
  <link rel="prefetch" href="/about.html">

  <!-- Script: defer = nach HTML-Parse -->
  <script src="app.js" defer></script>
</head>

<body>
  <!-- LCP-Bild mit hoher Priorität -->
  <img src="hero.jpg" alt="Hero"
       fetchpriority="high">

  <!-- Lazy-geladenes Bild -->
  <img src="foto.jpg" alt="Foto"
       loading="lazy"
       decoding="async">
</body>
Rechts · Merken
defer vs async

defer = nach HTML-Parse, in Reihenfolge. async = sofort wenn geladen, keine Reihenfolge.

LCP

Das grösste sichtbare Element (Largest Contentful Paint). fetchpriority="high" beschleunigt es.

decoding="async"

Browser darf Bild-Dekodierung im Hintergrund machen.

25 Best Practices & Validierung

Regeln und Gewohnheiten, die gutes HTML ausmachen — und Tools, um es zu prüfen.

  • Semantik vor Styling — erst das richtige Tag, dann CSS
  • Immer alt-Attribute — auf jedem <img>
  • Labels für Inputs — jedes Formularfeld braucht ein Label
  • lang-Attribut — auf <html> setzen
  • Keine deprecated Tags — kein <font>, <center>, <marquee>
  • Heading-Hierarchie — h1 → h2 → h3, keine Sprünge
  • Validieren — validator.w3.org findet Fehler
  • Lighthouse — Chrome DevTools → Audit für Performance, A11y, SEO
